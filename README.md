# 제품 런칭 비서 (PWA)

자사 브랜드 제품을 소싱부터 판매까지 **공장 현장에서 스마트폰으로** 관리하는 앱.
홈 화면에 설치하면 주소창 없는 전체화면 앱으로 뜨고, 오프라인에서도 그대로 동작한다.

## 실행

```bash
npm install
npm run dev      # 개발 서버
npm run test     # 계산 로직 + UI 스모크 테스트
npm run build    # 타입 체크 + 프로덕션 빌드
npm run preview  # 빌드 결과를 서비스워커까지 포함해 확인
```

## 주요 기능

| 탭 | 내용 |
|---|---|
| 홈 | 오늘의 비서 브리핑(지연·임박·출시 위험), 프로젝트 카드 |
| 체크리스트 | 6단계 32개 항목 · 담당자/마감일/현장 메모/사진 · 단계별 비서 도구 |
| 원가·마진 | BOM 5그룹 상세 원가 → 채널별 공헌이익·마진율·손익분기 ROAS 동시 비교 |
| 리포트 | A4 4~5페이지 인쇄/PDF (개요 · 작업지시 · 원가명세 · 마진+QC · 라벨사양) |
| 더보기 | 채널 요율 편집, JSON 백업/복원, 저장공간 |

**현장 비서 도구 3종** — 체크리스트 항목의 🔧 버튼에서 바로 열린다.

- **QC 사진 기록장** (STEP 2) — 불량을 촬영해 유형·심각도·수량으로 집계
- **한글표시사항 생성기** (STEP 3) — 혼용률 100% 검증 + 세탁기호 + 라벨 문구 자동 조합
- **안전재고·발주점 계산기** (STEP 4) — 리드타임 기반 ROP·발주수량, 파렛트 적재

## 데이터

전부 기기 안(IndexedDB)에만 저장된다. 서버도, 로그인도 없다.
기기를 옮기거나 백업하려면 **더보기 → 내보내기**로 JSON을 받아 두고, 새 기기에서 **복원**한다.
사진은 저장할 때 장변 1600px / JPEG로 압축된다(한 장당 보통 200~400KB).

## 핵심 계산식

```
제조원가 A = (그룹1~4 합) × (1 + 로스율%) + 그룹5 기타
             ※ 로스율은 자재·임가공에만. 인증비 상각 등에는 곱하지 않는다.

공급가   = (판매가 + 고객부담 배송비) ÷ 1.1      (VAT 포함 기준일 때)
수수료   = (판매가 + 고객부담 배송비) × 수수료율 + 건당 고정비
공헌이익 = 공급가 − 제조원가A − 수수료 − 물류비 − 기타 변동비
마진율   = 공헌이익 ÷ 공급가
BEP ROAS = 결제금액 ÷ 공헌이익          (공헌이익 ≤ 0 이면 '불가')
```

> ⚠ 채널 수수료 기본값(스마트스토어 5.85%, 쿠팡 10.8% 등)은 **참고용 추정치**다.
> 카테고리·계약에 따라 달라지므로 **더보기 → 판매 채널 수수료**에서 실제 정산 요율로
> 고친 뒤 `[확인함]`을 눌러야 비교표의 '요율 확인' 배지가 사라진다.

## 휴대폰에 설치

1. `npm run build` 후 GitHub에 올리고 [Vercel](https://vercel.com)에 연결 (무료).
   `vercel.json`에 SPA 라우팅 설정이 들어 있어 추가 설정이 필요 없다.
2. 폰 브라우저로 배포 주소 접속 → **홈 화면에 추가**
3. 이후 아이콘으로 열면 전체화면 앱으로 실행된다.

## 구조

```
src/
├─ db/        스키마 · Dexie · repo(저장소 계층) · 백업
├─ domain/    순수 계산 함수 (cost · margin · inventory · label · progress) + 테스트
├─ data/      체크리스트 템플릿 · 채널 프리셋 · 세탁기호
├─ hooks/     useLiveQuery 래퍼 — 어디서 고쳐도 열린 화면이 즉시 갱신
├─ components/ 레이아웃(하단 탭바) · UI 프리미티브 · 사진
└─ features/  home · project · checklist · tools · cost · report · settings
```

`domain/`은 DB·React에 의존하지 않는 순수 함수라 테스트로 전부 검증된다.
UI에서 저장소를 직접 부르지 않고 `db/repo/`만 거치므로, 나중에 Supabase 같은
원격 DB로 바꿀 때 repo 계층만 교체하면 된다.
